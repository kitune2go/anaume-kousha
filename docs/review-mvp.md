### 1\. 最も重大なバグ：住宅が完成すると土が増殖するwww

重大度：高

`build(p)` という住宅竣工処理に、次のコードがあります。

```javascript
p.cells.forEach(c => {
  c.h = c.base;
  c.robotFill = 0;
  c.bld = 'house';
});
```

建設業者は住宅の基礎を掘り、その土を周囲に積み上げます。しかし住宅が完成すると、掘った部分の地盤高が元に戻されます。

つまり、土を戻していないのに、地面が勝手に復活する。

基礎9マスをそれぞれ1.6掘ると14.4単位の土が出ますが、竣工処理によって相当量の地盤が無から復活します。

これは土砂保存を売りにしたシミュレーションとして致命的です。基礎の深さを維持したまま建物を建てる処理へ変更すべきです。

### 2\. 運搬ロボットの存在意義が弱い

`findSource()` を見ると、埋戻ロボット自身が採土場や土砂置き場から土を取得できます。

つまり、運搬機がいなくても埋戻機が採土場まで歩いて土を取りに行ける。

それでは物流設備の配置や輸送経路の設計が、必須の問題になりません。

改善するなら、埋戻機は原則として土砂置き場から補給し、運搬機が採土場から置き場まで輸送する役割を持たせる。そうすれば、運搬機が渋滞した途端に埋戻機が土砂不足で停止するという、面白い連鎖が発生します。

### 3\. ロボットが何を考えているのか分からない

これはゲームデザイン上、非常に大きいです。

A\*経路探索や衝突回避は実装されています。ロボットは経路を再計算し、通れない場所を一定時間避けます。

しかし、プレイヤーに十分な診断情報が提供されていません。

例えば、ロボットが停止したときに、それが「土砂不足」「経路なし」「他機との渋滞」「仕事がない」のどれなのか、画面だけでは判別しにくい。

自動化シミュレーションにおいて、観察できない自動化はストレスになります。

ロボットをタップすると現在の作業、積載量、目的地、移動予定経路が表示される仕組みが必要です。

### 2\. シーズン1のクリア条件

最終ステージでは次の3条件を満たせば合格とします。数値は初期の調整案です。

* 道路の稼働率が平均80%以上

* 公社の資金が枯渇しない

* 致命的な作業停止が一定時間以上継続しない

人間同士の喧嘩が終わる必要はありません。

そして、シーズン終了後にも同じ街を無期限に観察・改造できる「フリーモード」を用意します。

### 3\. 拡張可能なゲームエンジンの設計

現行HTMLでは、`T_LIMIT = 600`、住宅3棟、道路健全度80%などがゲーム本体に直接書かれています。

これらをステージ定義データへ移動します。

ステージ管理システム

シーズン・進行状況・クリア判定

地形・物理

穴・盛土・道路・衝突

人間AI

工事・要求・対立・行動

ロボットAI

作業・物流・経路探索

分類ルール

保護・撤去・保留・優先

共通の3D表示・操作UI

Three.js・指示画面・状態診断・結果報告

ステージ追加時は、共通エンジンを呼び出して、マップ、住民、ロボット、初期資金、使用可能機能、クリア条件を設定します。

例えば、第3話なら以下のようになります。

```javascript
const stage = {
  id: "S1-03",
  title: "ここは私の土地です",
  map: "town_01",
  duration: 600,

  humans: [
    { type: "resident", behavior: "claim_land" },
    { type: "resident", behavior: "use_road" }
  ],

  robots: {
    filler: 2,
    carrier: 1
  },

  mechanics: [
    "walls",
    "classification",
    "pathfinding"
  ],

  victory: {
    roadAvailability: 0.8,
    maxDeadlockTime: 30
  }
};
```

これは設計例であり、まだ現行HTMLがこの形式を読み込めるわけではありません。

### 4\. 将来のステージ追加方法

Season 1：掘るなとは言っていない。

開発対象

基礎工事、物流、境界争い、障害物分類。

Season 2：その土地には理由がある。

老朽化したインフラ、土地利用の変更、所有者不明の施設、撤去と保存の衝突。

Season 3：誰の仕事ですか。

複数の公社、民間委託、設備の共有、指示の競合、責任区分の問題。

シーズン2以降は現時点では構想のみです。新しい物理法則やAI行動が必要なら、独立した機能モジュールを追加します。既存ステージの処理を書き換えずに済むことを基本とします。

### 5\. 開発上の重要な決定

ステージ進行と街の永続運営を分離します。

ステージモードでは毎回決められた初期状態から始めることで、プレイヤーの成績比較やバグ再現を容易にする。

一方、フリーモードでは街の地形、ロボット、建設物、作業命令を保存し、好きなだけ運営できるようにする。

これなら新ステージを追加しても、以前のセーブデータが破綻する危険を抑えられます。

また、乱数シードとシミュレーションの更新刻みを固定できるようにして、同じ条件のテストを再現可能にします。

### 次の開発目標

最初から5ステージを一度に作るのではなく、第1話と第2話を共通エンジン上で切り替えられるところまで作るのが最初の到達点です。

二つのステージを、コードを複製せず、設定データの差し替えで動かせれば、拡張構造の第一段階は成功です。

そしてシーズン1を通して変わらない原則は、

人間は自分の事情で行動する。ロボットは与えられた規則で行動する。プレイヤーは、その組み合わせから生じる問題に対処する。

ということです。

「人間に任せてはいけない」という結論をゲームが教える必要はありません。

遊んでいるプレイヤーが勝手に「もう人間に任せてはいけないwwww」と言い出すなら、それが一番面白いわけです。
